# The browser demo

`index.html` plays the scenes of `cargo run --locked --example watchdog`, run by the real Guard Dog code (Judge C's egress checker and the safe renderer for outside text) compiled to WebAssembly. It makes no network request: the page's Content-Security-Policy says `connect-src 'none'`.

| File | What |
|---|---|
| `index.html`, `demo.js`, `theme.js` | The page, in the site's style. Plain JavaScript, no framework; all text goes in with `textContent`. GSAP and the Inter font are the site's own vendored copies in `../vendor/`. |
| `watchdog.wasm.js` | The engine: a WebAssembly module as base64 in a script file. The page loads this, because its policy forbids fetching a `.wasm` file. Generated by `build.sh`; never edit it. The `.wasm` itself isn't committed. |
| `build.sh` | Rebuilds `watchdog.wasm.js` from `crates/gd-demo` and `crates/gd-demo-wasm`, writes the `.wasm` under cargo's target directory, and prints its size and SHA-256. Needs the toolchain from `rust-toolchain.toml` (it adds the wasm target the first time), `jq` and `strings`. |

## Checking the engine

The engine is 444,355 bytes (434 KB). Two hashes are pinned, and each catches something different:

```
058520333f23b623f2dc5dbec05cab31e8e67e47edec3fcf13a4f0cc483cb479  watchdog.wasm
52b867d0700237c32cf3003eac8eeef1d33982eff535e01d7102b789d5c9ab11  events.json
```

- `watchdog.wasm` is the SHA-256 of the WebAssembly module inside `watchdog.wasm.js`. `cargo test` decodes the committed script file and fails if the module isn't this one, so a hand edit or swap of the file is caught. It does not prove the module was built from this source.
- `events.json` is the SHA-256 of the events JSON the scenes produce from source, which is what the engine hands the page (`cargo run --locked --example events_hash` prints it). `cargo test` recomputes it, so a change to a scene's text or verdict fails until the engine is rebuilt with `build.sh` and both hashes are pinned again. It does not prove the committed module produces that JSON.

Only rebuilding and comparing proves the module matches the source: run `docs/demo/build.sh` and compare the two hashes it prints.

The module hash comes from Rust 1.99.1 (the pinned toolchain) on macOS aarch64. The build maps your home, cargo and registry folders to fixed names, so a git or a sparse registry gives the same bytes; a different operating system or toolchain may not. If your hash differs, the build is the proof, not the number.

Until a CI step rebuilds and compares the engine (a later change, because it touches `.github/`), I rebuild and check it by hand at release time.
