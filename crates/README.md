# Crates

One line per crate: what it owns. A new crate arrives only when its first real caller does (sensors, advisories and notifications come next).

| Crate | Owns |
|---|---|
| `guard-dog` | The `guard-dog` binary: the command line, and later the daemon and the local status page. It holds no logic of its own; that lives in the library crates. `--version` names the release, plus the exact git commit for release builds (which set `GD_GIT_COMMIT`); local builds say "development build". |
| `gd-core` | The shared types. `Untrusted<T>` is outside text as a type the compiler tracks: it can't be printed, compared or passed on except through `escape_for_terminal()`, `escape_for_html()` or a greppable `expose_untrusted()`, and every use of the last one needs a reviewer's OK. The fact model (`fact.rs`, `view.rs`): `Fact`, `Observed<T>` (`Seen` or `Unknown`, with no default and no bool conversion), the ordered detection `Method`, validated id and version types, and `setup_view`, which derives setup-level facts from per-service facts. `Untrusted<T>` also serialises as `{"untrusted": ...}`. `Finding` and `Advisory` are placeholders until the matcher is built. `privilege` proves credentials narrow with no IO: an LND macaroon must allow exactly `info:read`, a Core Lightning rune only `getinfo` with no parameters, a Bitcoin Core login must be allowed the two calls Guard Dog needs and refused three canary calls, and the process must not be root; anything wider is refused with a plain-English fix. |
| `gd-egress` | Judge C's tooling: makes the planted canary secrets and checks an egress capture against `allowlist.toml`, decoding gzip, deflate and brotli request bodies before it scans them. Test tooling only; never in a release. |
| `gd-notify` | Alerts as private Nostr direct messages (NIP-17), to the regtest lab's own relay only (`ws://strfry:7777` and the other lab host names, which have fixed addresses in the lab's own subnet, 172.29.208.0/24, set in `lab/compose.yml`; there is no DNS lookup, and anything else is refused; the 10 second limit covers the whole conversation, even a relay that sends one byte at a time). Builds NIP-44 v2 encryption, the NIP-59 seal and gift wrap, and BIP-340 signatures from RustCrypto parts (the `nostr` crate needs libsecp256k1, which `deny.toml` refuses). Guard Dog's own key lives in `<state dir>/notify.key` (0600, folder and file both owned by the user running Guard Dog, removed if its write fails; the key store runs only on Linux, where POSIX ACL entries are bounded by the mode bits' group mask, and other systems get an `UnsupportedPlatform` error; the state folder must also be on a local filesystem (ext2, ext3, ext4, xfs, btrfs, f2fs, tmpfs or overlay, read from `/proc/self/mountinfo`), because on NFS, SMB, FUSE, 9p or ZFS the server or driver decides who can read the key and the mode bits prove nothing, so anything else is refused with `NotLocalFilesystem` before any key is created or read; secret values are wiped from memory when dropped, best effort: copies the compiler or the operating system make cannot be reached), never the user's `nsec`. Turns an `Alert` of validated values into one plain-text message, with outside text escaped, capped and quoted; sends only critical, high or unknown-severity findings, at most 20 messages per run plus one summary that says how many findings were not sent and why (over the cap, medium or low, or on another chain); and sends nothing unless the node's chain is regtest or signet (a single alert on another chain is dropped and counted, never sent). A recipient is an npub only. `send_alerts` is the crate's only public way to send (the raw publisher and the event builder are crate-private; integration tests use a `#[doc(hidden)]` builder that never touches the network), and it sends nothing, not even a summary, when no alert is eligible. Wraps carry no sender copy on purpose: under NIP-17 a sender may wrap a copy to itself, but Guard Dog's alert key is a send-only notifier. Relay acks must be exactly `["OK", id, bool, text]` and the first answer per event stands. Nothing here logs; an app that installs a logger must not enable TRACE for `tungstenite` (it prints frame contents), keep it at WARN. The path to the state folder is walked one name at a time like OpenSSH's `secure_path` (symlinks followed by hand, at most 40, no `.`, `..` or trailing `/`), and every folder passed through must belong to root or the running user and not be writable by others unless sticky (a parent made under umask 002, mode 0775, is refused on purpose). Before sending, it looks up the recipient's kind-10050 inbox list on the relay and sends only if the newest validly signed one lists that relay. `Event`'s `Debug` shows only the kind and the tag count. Time and randomness come in through injected sources. |
| `gd-demo` | The "watch it catch a leak" demo: five scenes run by the real checks (the safe text renderer, Judge C's egress checker), as `cargo run --locked --example watchdog`, and the same events for the page in `docs/demo/`. Demo only; never in a release. |
| `gd-demo-wasm` | The browser build's two exports (`demo_run`, `demo_len`), compiled to WebAssembly by `docs/demo/build.sh`. Demo only. It is the one crate that relaxes `unsafe_code` from `forbid` to `deny`, because a WebAssembly export needs `#[unsafe(no_mangle)]`; each of its two functions carries its own `allow`, and there are no `unsafe` blocks. |
| `gd-advisories` | Advisory intake, pure and with no network: OSV 1.9.2 records read into bounded typed data (`parse_advisory`: size, depth, count limits, duplicate keys refused, outside text kept `Untrusted`, anything not understood listed as a gap) and one canonical form for package names (`canonical_package`: PyPI by PEP 503, GIT URLs, Go exact). Version ordering and range matching come in later steps. |

The judge tests (Judges A, B and D) and the tests for `tools/record-setup.sh` live in `crates/gd-core/tests/` until a judges crate earns its place.

Rules that hold in every crate: no `unsafe` (the workspace forbids it), no network access outside the allowlist, no shell commands built from outside text, and the core works with no AI model.
